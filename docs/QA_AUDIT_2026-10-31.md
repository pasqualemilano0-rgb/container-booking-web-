# Audit Container Booking — 31 ottobre 2026

## Esito

**Versione controllata:** web GitHub Pages v0.28.  
**Controlli unitari:** 71 JavaScript su 71 e 70 Python su 70 superati (workflow `41217004381`).  
**Browser automatico:** 5 risoluzioni (320, 390, 432, 768, 1280 px) superate, percorso CNT → TFG → CNT → SCT → Napoli, nessun errore JS non gestito e nessun overflow orizzontale (workflow `41217004398`).  
**Ambiente di test:** Chromium Linux con emulazione viewport/touch Android e risposte portuali simulate; *non* è un collaudo su telefono fisico.

## Bug corretti

1. **Blocco Javascript critico:** apostrofo non escapato all'interno di una stringa in `app.js` interrompeva l'inizializzazione dell'app. Corretto nel commit `b2d5b827`. I test unitari precedenti non lo avevano intercettato; ora il workflow QA Chromium verifica la pagina davvero eseguita.
2. **Pannelli CNT/TFG incoerenti:** radio selezionato e pannello visibile non sempre sincronizzati. La selezione è centralmente risincronizzata in `driver-ui.mjs`, con protezione CSS e test CNT → TFG → CNT.
3. **Aggiornamenti ridondanti:** il pulsante TFG non esegue due richieste di rete quando il cambio radio avvia già il controllo. Se TFG è già selezionato, il pulsante può forzare una lettura.
4. **Aggiornamento manuale del sito:** la v0.27 verifica la versione web ogni 4 minuti e l'eventuale nuovo codice viene caricato solo quando l'autista non sta editando o consultando un risultato. I dati del terminal attivo vengono aggiornati ogni 5 minuti, alla selezione, al ritorno in primo piano e al ritorno della connessione; Android può sospendere l'app in background.
5. **Suite di test malformata/obsoleta:** corretta l'indentazione in `tests/test_web_markup.py`, la concatenazione accidentale di due assertion e i confronti con eventi/versioni ormai superati.
6. **CSP inefficace:** rimossa la direttiva `frame-ancestors` dal tag `meta`, dove i browser la ignoravano (v0.28). Se necessaria, configurarla come header HTTP nel provider hosting.
7. **Fast Corridor != gate cut-off:** nel programma TFG, `CUSTOM CLOSE TIME`, `Fast Corridor CUT OFF` e accettazione nave restano campi distinti. Non viene inventata una chiusura generale a partire dal Fast Corridor (v0.23).

## Rischi non risolti

| Priorità | Problema | Rischio | Azione |
|---|---|---|---|
| **Alta** | Le pubblicazioni GitHub Pages avvengono indipendentemente dall'esito della QA. | Una release non collaudata può diventare pubblica. | Collegare la distribuzione a un workflow con gating e branch protection; non confondere `Pages success` con `QA success`. |
| **Alta** | Il controllo booking TFG non è automatizzato con protocollo verificato/autorizzato. | Il programma navi può indicare `ACCETTA CARICO` senza confermare il booking o il luogo di scarico. | Usare il controllo booking ufficiale immediatamente prima della consegna; integrare solo un accesso documentato e autorizzato. |
| **Media** | Il portale TFG dichiara un orario di aggiornamento del programma indipendente dall'ora della lettura. | Una lettura API riuscita non significa dati ufficiali aggiornati. | Mostrare sempre i due orari distinti e non promuovere a confermati gli stati troppo vecchi. |
| **Media** | Nessun test su hardware Android fisico, webview/app wrapper, perdita e ritorno rete reale. | Differenze di permission clipboard, gestione cache, standby, browser e performance. | Collaudo diretto Android con screenshot/bug report e test in condizioni di connettività variabile. |

## Cosa testano davvero le verifiche

- Le suite Node e Python coprono parser, matching navi/viaggi, timestamp e scadenze, stato Dry/Reefer, segnalazione di dati vecchi, colonne TFG, gestione snapshot e markup.
- La QA Chromium avvia un server locale, usa solo **dati fittizi** e prova selezione dei porti/terminal, navigazione e assenza di crash/overflow tra 320 e 1280 pixel.
- I programmi portuali reali sono acquisiti dal workflow GitHub separato; il successo dell'acquisizione non è una conferma che il terminal abbia aggiornato il proprio sistema interno.
- Un `HTTP 200` ricevuto tramite un connettore autenticato non dimostra accessibilità anonima da GitHub Pages.

## Decisione operativa

Non certificare ancora Container Booking come sostituto dei portali ufficiali né come sistema di autorizzazione alla consegna. Finché non si risolvono API TFG pubblica/autorità del booking, accessibilità del backend e test Android fisici, ogni esito di accettazione è informativo e richiede verifica sul sito del terminal.
